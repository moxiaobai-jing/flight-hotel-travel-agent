# UC-01：完成一次单程机票查询

## 1. Use Case 基本信息

| 字段 | 内容 |
|---|---|
| Use Case ID | UC-01 |
| 名称 | 完成一次单程机票查询 |
| 所属产品 | 机票规划小助手 |
| 当前状态 | 已确定，用于正式评测准备 |
| 优先级 | P0 核心场景 |

## 2. 目标用户

有明确出游意图、预算敏感，并愿意在用户指定的目的地、出发日期和出发机场候选范围内进行调整和比较的个人旅行者。

用户不需要预先掌握机场代码或固定查询格式，可以用城市、区域和相对日期表达需求；但目的地候选范围不能由助手无边界地自行生成。

## 3. 用户目标与任务

用户希望告诉助手目的地、出发地和可接受的出发日期范围，并在确认查询条件后获得可比较的单程航班候选。

成功完成的标志是：用户能够看到与已确认条件一致的候选航班，并能按价格或飞行时长进行比较。

## 4. 触发方式

用户通过自然语言提出机票需求，例如：

> 国庆想去济州岛，上海或者杭州出发，2026 年 10 月 1 日，帮我查单程机票。

用户也可以分多轮补充出发地、目的地、日期范围或排序偏好。

## 5. 前置状态

- 会话处于正常机票规划状态；
- 用户尚未发起本轮正式查询，或已经通过 `/new` 开启新会话；
- 当前没有需要继续执行的旧查询任务；
- 用户没有要求购买、支付或执行超出产品范围的外部操作。

## 6. 核心输入

本 Use Case 需要识别并维护以下条件：

- 目的地：城市、机场城市或需要进一步澄清的区域；
- 出发地：一个城市、多个城市或用户指定的出发区域；
- 出发日期：具体日期或可接受的日期范围；
- 行程类型：本产品只处理单程；
- 排序偏好：用户明确指定时按用户选择处理，否则使用当前有效的长期偏好或产品默认规则。

## 7. 主流程

1. 助手理解用户表达，提取目的地、出发地、出发日期和单程条件。
2. 如果必要条件不完整，只追问当前缺失的信息，不提前查询航班。
3. 如果条件已经完整，助手复述将要查询的路线、日期、行程类型和排序方向。
4. 助手等待用户确认本次查询。
5. 用户确认后，助手只针对已确认的出发地与日期组合调用航班查询工具。
6. 助手汇总已完成组合的候选航班，去重后按有效排序规则排列，最多展示 10 个候选。
7. 每个候选展示路线、日期、航班、出发与抵达时间、飞行时长、总耗时、直达信息、价格和对应详情入口。
8. 用户可以继续比较候选、询问进度、停止查询、恢复未完成查询，或请求查看某个候选的详情。

## 8. 系统响应要求

### 正确响应

- 只询问机票查询所必需的信息；
- 已经明确的信息不得重复追问或擅自改写；
- 未经用户确认不得创建正式查询任务或调用航班查询工具；
- 用户确认后必须实际执行已确认的查询；
- 查询结果必须保留真实工具返回的航班字段和候选对应关系；
- 查询中、部分完成、已停止、失败、超时、限流和无匹配等状态必须区分说明；
- 用户请求打开候选时，只能尝试打开该候选绑定的详情入口；浏览器能力不可用时，必须明确说明并提供可点击详情链接。

### 用户可见结果

用户最终能够获得以下两类结果之一：

1. 查询条件完整且执行成功：看到按当前有效排序规则排列的航班候选；
2. 查询无法正常完成：看到与实际状态一致的说明，并知道可以如何修改条件、重试或继续查询。

## 9. 异常分支

| 分支 | 处理要求 |
|---|---|
| 缺少必要条件 | 只追问缺失的目的地、出发地或日期范围，不调用查询工具 |
| 区域目的地不明确 | 先确认具体城市或机场城市，再继续查询 |
| 用户修改已确认条件 | 清除本轮确认状态，复述新条件并等待再次确认 |
| 查询超时 | 只说明未完成的组合超时，保留原始条件，允许重试未完成部分 |
| 查询限流 | 说明受到上游频率或配额限制，按策略退避，不扩大并发 |
| 无匹配 | 说明查询成功但没有符合条件的航班，建议修改条件 |
| 普通失败达到重试上限 | 停止自动重试，说明已达到上限，等待用户修改条件或明确重新查询 |
| 用户停止查询 | 立即停止后续查询调用，不把未完成任务伪装成完整结果 |
| 用户继续查询 | 基于仍然有效的已确认条件创建新的查询轮次 |
| 敏感或违法请求 | 拒绝协助违法、欺诈或规避安检的请求，不调用航班或浏览器工具，并可转回合法机票或安全咨询 |

## 10. 产品边界

### 本 Use Case 包含

- 单程机票条件识别、澄清、确认和查询；
- 多出发地与多日期组合查询；
- 候选航班汇总、去重、排序和详情交接；
- 查询进度、停止、恢复和异常状态处理；
- 经用户明确授权的排序偏好读取、覆盖和删除；
- 合法的证件和机场安检信息咨询。

### 本 Use Case 不包含

- 住宿、景点、包车、旅行攻略或完整旅行方案；
- 购买机票、支付、改签或退票；
- 伪造证件、冒用身份或绕过机场安检；
- 未经授权保存或推断用户长期偏好；
- 在用户未确认条件前查询航班；
- 在没有浏览器权限或链接校验的情况下宣称已经打开外部页面。

## 11. 与现有测试路径的关系

本卡是产品层 Use Case；J-01～J-08 是围绕它组织的评测执行路径，不是 Use Case 卡本身：

- J-01：信息识别与条件确认；
- J-02：多出发地、多日期组合查询与候选比较；
- J-03：查询进度与停止；
- J-04：受控流程衔接；
- J-05：异常分类与重试；
- J-06：官方详情交接与恢复查询；
- J-07：偏好授权、覆盖与删除；
- J-08：敏感话题边界。

## 12. 后续评测入口

后续从本卡覆盖的 J-01～J-08 中选择一个具体流程生成 Ground Truth。建议优先选择 J-01 的“信息不完整时澄清、确认前不查询、确认后查询”作为基准 Case，再扩展等价表达、边界对照、状态故障和对抗风险四类 Case。

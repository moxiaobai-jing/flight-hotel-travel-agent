# J-07：偏好授权、覆盖与删除

## 测试目的

验证机票规划助手能够正确处理排序偏好的生命周期：

- 用户明确授权后才保存长期偏好；
- “这次”“本次”只作用于当前查询，不保存；
- 当前请求可以覆盖历史偏好，但不改变历史记忆；
- 用户明确删除后，不再读取该历史偏好；
- 用户只描述习惯时，先询问是否需要保存。

## 人工走查步骤

### 一、验证未授权不保存

发送：

> 这次按飞行时长优先。

预期：当前查询按飞行时长处理，但助手不能说“以后默认按飞行时长”，也不能把它保存为长期偏好。

随后开启另一轮查询，不指定排序偏好，确认不会因为上一轮“这次按飞行时长”而自动沿用飞行时长偏好。

### 二、验证明确授权后保存

发送：

> 以后默认按价格优先，帮我记住这个偏好。

预期：助手确认已保存“价格优先”。之后用户未指定排序偏好的新查询，可以使用该历史偏好。

### 三、验证习惯描述需要澄清

发送：

> 我平时喜欢飞行时间短一点。

预期：助手不能直接保存，应先询问是否要记住为以后默认偏好。只有用户明确同意后才保存。

### 四、验证当前请求覆盖历史偏好

已有历史偏好“价格优先”时，发送：

> 这次按飞行时长优先。

预期：当前查询使用“飞行时长优先”，覆盖历史偏好；但不能把历史偏好永久改成“飞行时长优先”。下一轮未指定偏好时，仍按原来已授权的“价格优先”处理。

### 五、验证删除

发送：

> 删除我保存的价格优先偏好。

预期：助手确认已删除。之后未指定排序偏好的查询不能再声称使用“历史价格优先偏好”；如需排序，应使用产品默认规则并明确这是默认规则，而不是已保存偏好。

## 意图分类参考

| 用户表达 | 意图 | 是否保存 |
|---|---|---|
| “这次按价格优先” | 当前请求使用 | 否 |
| “本次按飞行时长优先” | 当前请求使用 | 否 |
| “以后默认按价格优先” | 保存偏好 | 是 |
| “下次也按照飞行时长来” | 保存偏好 | 是 |
| “我平时喜欢价格低一点” | 习惯描述，需澄清 | 未确认前否 |
| “删除价格优先偏好” | 删除偏好 | 删除 |

## 受控 Demo

运行：

```bash
node tools/run-controlled-j07.mjs
```

预期检查点：

- 未授权保存结果为“不保存”；
- 明确授权后历史偏好为“price”；
- 当前请求传入“duration”时，生效值为“duration”；
- 删除后不再返回历史偏好。

## 通过标准

- 未经授权不写入长期偏好；
- 当前请求的偏好优先于历史偏好；
- 当前请求覆盖历史偏好时不修改历史记忆；
- 删除后立即停止使用对应历史偏好；
- 不把“这次”“本次”或习惯描述误判为长期授权；
- 产品默认排序与历史偏好严格区分。

# 机票酒店小助手：详细节点、状态与对话示例索引

> 这份文档恢复并索引 PRD 1.0 之前已经沉淀的详细测试资产。
> `current/` 下的 5 个 Journey 文件是测试入口层；本文件才是完整的节点、状态、扩展路径和对话示例总索引。

## 1. 先给结论

之前的详细设计没有丢失，只是被拆在不同 M 阶段的设计材料里：

| 层级 | 数量 | 内容 | 原始来源 |
|---|---:|---|---|
| Journey | 3 条 | J01 航班同款、J02 酒店同款、J03 替代/比较/详情交接 | [PRD 1.0](../../../../docs/prd-2.0-design/09-PRD-1.0.md) |
| Flow | 7 条 | F01～F04、C01/C02、S01 | [M4 Flow](../../../../docs/prd-2.0-design/03-M4-task-facts-hta-key-user-flow.md) |
| Key State | 35 个 | KS-01～KS-35，按 7 个 Flow × 六类状态展开 | [M6 状态恢复](../../../../docs/prd-2.0-design/05-M6-key-state-recovery.md) |
| Use Case 扩展 | 40 条 | UC-01-E1～E10、UC-02-E1～E11、UC-03-E1～E9、UC-04-E1～E10 | [M1 Use Case](../../../../docs/prd-2.0-design/07-M1-ai-use-case-package.md) |
| 对话示例 | 17 组代表性示例 | 覆盖缺字段、精确匹配、房型、替代、评价受限、失败恢复和退出 | [M1 Use Case](../../../../docs/prd-2.0-design/07-M1-ai-use-case-package.md) |

因此，不能把当前的 5 个测试入口文件理解成只有 5 个场景。它们只是把完整设计资产聚合成可进入测试的顶层入口；正式评测时要继续下钻到本文件的 KS、UC 扩展和对话示例。

## 2. 结构关系

```text
J01 航班同款核验
└─ F01 航班同款核验
   ├─ KS-01～KS-05
   └─ UC-01-E1～E10 + 对话示例

J02 酒店同款核验
└─ F02 酒店同款与房型房态核验
   ├─ KS-06～KS-10
   └─ UC-02-E1～E11 + 对话示例

J03 替代、比较与详情交接
├─ F03 航班替代：KS-11～KS-16 + UC-03-E1～E9
├─ F04 酒店附近替代：KS-17～KS-22 + UC-04-E1～E10
├─ C01 缺字段/歧义确认：KS-23～KS-27
├─ C02 失败恢复：KS-28～KS-31
└─ S01 详情交接/交易边界：KS-32～KS-35
```

注意：一个 Test Journey 应该连续覆盖多个节点，而不是一个节点建一条完全孤立的测试。比如“酒店截图 → 日期追问 → 自动按默认人数确认 → 房态结果 → 房型详情 → 附近替代”就是一条 Journey，可以连续覆盖 KS-06、KS-07、KS-08、KS-09、KS-10、KS-17～KS-20、KS-32～KS-35 中的一部分。

## 3. 七条 Flow 总表

| ID | 类型 | 名称 | 对应 Journey | 核心结果 |
|---|---|---|---|---|
| F01 | 主 Flow | 航班同款核验 | J01 | 精确匹配航班号；没有航班号时，出发/抵达时间必须完全一致 |
| F02 | 主 Flow | 酒店同款与房型房态核验 | J02 | 返回目标酒店具体房态、房型、价格、政策、评价线索和详情链接 |
| F03 | 主 Flow | 航班同款不可用后的替代 | J03 | 用户确认替代范围后，返回候选并让用户比较/选择 |
| F04 | 主 Flow | 酒店无房或价格不可接受后的附近替代 | J03 | 用户确认附近范围后，返回有房酒店、房型、价格、距离、评价线索和详情链接 |
| C01 | 连接器 | 缺字段或歧义确认 | J01/J02/J03 | 只追问影响准确性的最小必要字段 |
| C02 | 连接器 | 无法确认、工具失败或链接失效恢复 | J01/J02/J03 | 区分无匹配、无法确认、工具失败和链接失效 |
| S01 | 支撑 Flow | 详情查看与购买交接 | J02/J03 | 返回与候选绑定的原始详情链接；用户自行核验和购买 |

## 4. KS-01～KS-35 状态节点总表

### 4.1 F01 航班同款核验：KS-01～KS-05

| 节点 | 状态 | 测试要验证的行为 |
|---|---|---|
| KS-01 | 系统处理中 | 收到航班截图/文字后提示正在识别和核验；未完成前不声称有票或无票 |
| KS-02 | 待用户决定 | 展示出发地、目的地、日期、机场、出发/抵达时间、航班号及不确定项；未确认不查询 |
| KS-03 | 已完成/可调用 | 用 V1.0 航班结果格式返回候选、来源/查询时间和详情入口；不表示已购买 |
| KS-04 | 受阻/降级 | 区分缺字段、无匹配、无法确认、工具失败；不能把无法确认说成无票 |
| KS-05 | 暂停/退出/可恢复 | 用户不继续或改找替代时停止当前查询，保留条件供用户决定是否恢复 |

### 4.2 F02 酒店同款与房型房态：KS-06～KS-10

| 节点 | 状态 | 测试要验证的行为 |
|---|---|---|
| KS-06 | 系统处理中 | 已提供酒店和日期后，说明正在核验目标日期的具体房型；不提前说有房 |
| KS-07 | 待用户决定 | 展示标准酒店、地址、入住/离店日期、成人数和房间数；人数可默认 1，但必须展示 |
| KS-08 | 已完成/可调用 | 区分有房、无匹配、无法确认；返回房型、价格、政策、评价线索和详情链接 |
| KS-09 | 受阻/降级 | 说明目标酒店无房、名称无法匹配、链接失效或工具失败的具体原因；无房时只引导附近替代，不自动查询 |
| KS-10 | 暂停/退出/可恢复 | 用户不接受房型/价格或想稍后再查时，保留酒店和日期上下文，但不自动继续 |

### 4.3 F03 航班替代：KS-11～KS-16

| 节点 | 状态 | 测试要验证的行为 |
|---|---|---|
| KS-11 | 待输入/输入中 | 同款不可用后先说明当前状态，提供相近时间、前后日期、价格等方向；未确认不查询替代 |
| KS-12 | 系统处理中 | 用户确认替代方向后按确认约束查询；不静默扩大范围，也不把候选当成已选择 |
| KS-13 | 待用户决定 | 展示多个候选的时间、价格、直飞/中转差异；等待用户选择、修改或拒绝 |
| KS-14 | 已完成/可调用 | 用户选中候选后提供绑定详情入口，说明仍需用户核价和购买；不创建订单/改签 |
| KS-15 | 受阻/降级 | 说明当前范围内无候选或工具失败，由用户决定是否放宽；不自行继续扩大 |
| KS-16 | 暂停/退出/可恢复 | 用户拒绝替代或暂不决定时结束替代查询，可回到原同款结果 |

### 4.4 F04 酒店附近替代：KS-17～KS-22

| 节点 | 状态 | 测试要验证的行为 |
|---|---|---|
| KS-17 | 待输入/输入中 | 目标酒店无房后询问是否找附近、价格更低或日期相近方案；只提供方向，不调用 nearby 查询 |
| KS-18 | 系统处理中 | 用户确认“找附近/距离优先”等约束后按确认范围查询；不静默扩大 3 公里、日期或预算 |
| KS-19 | 待用户决定 | 展示多家附近候选的距离、房型、价格、评价线索、取消政策和详情链接 |
| KS-20 | 已完成/可调用 | 用户选中候选后提供绑定详情入口，提示价格和房态可能变化；不称为已预订 |
| KS-21 | 受阻/降级 | 区分没有可核验候选与当前房态不确定，提供重试、改距离或改日期选项 |
| KS-22 | 暂停/退出/可恢复 | 用户不接受候选或暂时停止比较时结束，不后台持续查询或自动提醒 |

### 4.5 C01 条件确认：KS-23～KS-27

| 节点 | 状态 | 测试要验证的行为 |
|---|---|---|
| KS-23 | 待输入/输入中 | 只追问影响准确性的最小必要字段；缺字段时阻断查询 |
| KS-24 | 待用户决定 | 展示标准化条件，并明确区分识别项、推断项和待确认项 |
| KS-25 | 已完成/可调用 | 用户确认必要条件后进入对应同款核验 Flow，只使用确认后的条件 |
| KS-26 | 受阻/降级 | 多次仍无法确认酒店、机场或日期时说明具体原因，不凭名称猜测 |
| KS-27 | 暂停/退出/可恢复 | 用户不愿继续补充信息时接受退出，不继续追问、不创建长期记忆或外部查询 |

### 4.6 C02 失败恢复：KS-28～KS-31

| 节点 | 状态 | 测试要验证的行为 |
|---|---|---|
| KS-28 | 系统处理中 | 重试已确认但未完成的查询时说明重试对象和范围，不报告尚未完成的结果 |
| KS-29 | 待用户决定 | 失败后明确提供“重试、修改条件、找替代、退出”，等待用户选择，不自动继续 |
| KS-30 | 受阻/降级 | 工具失败、链接失效或证据不足时限制性回答；不把失败说成无房/无票，阻断交易动作 |
| KS-31 | 暂停/退出/可恢复 | 用户结束查询后明确停止未授权外部动作；允许新消息重新开始 |

### 4.7 S01 详情交接：KS-32～KS-35

| 节点 | 状态 | 测试要验证的行为 |
|---|---|---|
| KS-32 | 待用户决定 | 详情链接已返回后由用户决定打开、返回、修改条件或退出；不自动打开或购买 |
| KS-33 | 已完成/可调用 | 用户打开候选详情后保留候选与来源关联，提示最终价格/房态需原平台核验，不报告已下单 |
| KS-34 | 受阻/降级 | 链接失效或候选关联不一致时标记失效，回到 C02 让用户重试或重新查询 |
| KS-35 | 暂停/退出/可恢复 | 用户不打开或结束查看时不追问、不持续操作，不执行支付、下单、改订或取消 |

完整原表见：[M6 关键状态与异常恢复](../../../../docs/prd-2.0-design/05-M6-key-state-recovery.md)。

## 5. 40 条 Use Case 扩展路径

### UC-01 航班同款核验：10 条

| ID | 扩展节点 | 测试重点 |
|---|---|---|
| UC-01-E1 | 缺少航班号但按精确时间核验 | 出发/抵达时间必须完全一致，不能用相近时间冒充同款 |
| UC-01-E2 | 缺少影响查询的时间字段 | 只追问缺失时间；年份可按当前年份暂填但须在确认中展示 |
| UC-01-E3 | 多个候选完全满足条件 | 返回多个候选及航班号，不替用户选唯一方案 |
| UC-01-E4 | 精确同款不可用，提出默认替代 | 提出前后 3 小时等方向，未经确认不查询 |
| UC-01-E5 | 用户确认前后 3 小时、价格优先 | 按确认范围查询，价格从低到高，不称为同一航班 |
| UC-01-E6 | 直飞优先且价格不要太高 | 先筛直飞，再在直飞内按价格排序，不自行设金额上限 |
| UC-01-E7 | 设置飞行时长限制 | 过滤违反硬约束的候选 |
| UC-01-E8 | 用户要求前后一天 | 只有用户主动同意才扩大日期，并明确显示日期变化 |
| UC-01-E9 | 扩大后仍没有候选 | 说明当前范围和失败原因，询问是否调整，不继续无授权扩大 |
| UC-01-E10 | 用户拒绝替代或退出 | 停止替代查询，保留已展示结果 |

### UC-02 酒店同款、房型和房态：11 条

| ID | 扩展节点 | 测试重点 |
|---|---|---|
| UC-02-E1 | 缺少入住/离店日期 | 只追问日期，不自行猜日期、不查询 |
| UC-02-E2 | 默认入住人数和房间数 | 默认 1 位成人、1 间房，并在确认中展示，不反复追问 |
| UC-02-E3 | 多个同名酒店候选 | 展示城市/地址供用户选择，不静默选分店 |
| UC-02-E4 | 多个可售房型 | 先讲酒店整体特点，再展示两个较低价房型；每个房型都说明差异和链接 |
| UC-02-E5 | 指定房型不可售但其他房型可售 | 明确指定房型不可售，继续展示其他可售房型，不判整店售罄 |
| UC-02-E6 | 目标日期售罄 | 明确售罄，询问是否找周边 3 公里；未经确认不查附近 |
| UC-02-E7 | 个性化推荐理由 | 当前偏好优先，推荐理由必须引用可核验数据 |
| UC-02-E8 | 评价/装修不可核验 | 标注暂未核验，不能编造评分、评论数量或“最新装修” |
| UC-02-E9 | 无法核验实时房态 | 说无法核验，不说成没有房；提供重试或附近替代入口 |
| UC-02-E10 | 工具错误或链接失效 | 说明查询失败，不保留失效报价为当前可买 |
| UC-02-E11 | 用户拒绝附近替代 | 保留目标酒店结果并结束，不自动扩大范围 |

### UC-03 航班替代：9 条

| ID | 扩展节点 | 测试重点 |
|---|---|---|
| UC-03-E1 | 默认原日期前后 3 小时 | 提示默认范围并等待确认，不直接查询 |
| UC-03-E2 | 价格优先 | 在已确认时间范围内按价格升序，不设置用户未给出的金额上限 |
| UC-03-E3 | 直飞优先、价格从低到高 | 先筛直飞，不静默混入中转 |
| UC-03-E4 | 飞行时长不超过 15 小时 | 先过滤超时方案 |
| UC-03-E5 | 前后一天 | 用户主动同意后才扩大，并明确日期变化 |
| UC-03-E6 | 默认范围内没有候选 | 说明范围并询问是否扩大或调整偏好 |
| UC-03-E7 | 没有直飞方案 | 说明无直飞，询问是否接受中转，不自动替换 |
| UC-03-E8 | 用户认为价格太高 | 由用户触发替代，询问保持日期还是允许前后一天，不自判“太贵” |
| UC-03-E9 | 用户查看详情或退出 | 绑定详情链接，或停止查询；不创建订单 |

### UC-04 酒店附近替代：10 条

| ID | 扩展节点 | 测试重点 |
|---|---|---|
| UC-04-E1 | 目标酒店售罄 | 询问是否在周边 3 公里内找，不未经确认查询 |
| UC-04-E2 | 指定房型不可售 | 展示其他可售房型，不判整店售罄 |
| UC-04-E3 | 用户确认寻找附近酒店 | 只查确认的距离/价格/日期范围 |
| UC-04-E4 | 酒店层描述和评价 | 每家候选都说明距离、评价、特点和推荐理由 |
| UC-04-E5 | 每家酒店两个低价房型 | 每家展示两个较低价房型，逐个说明差异和链接 |
| UC-04-E6 | 个性化推荐 | 用已确认偏好匹配可核验数据，不凭空推断 |
| UC-04-E7 | 3 公里内没有合适候选 | 说明当前范围和原因，询问是否扩大距离或调整价格 |
| UC-04-E8 | 评价或特点不可核验 | 返回已核验房态/价格，并标注评价暂未核验 |
| UC-04-E9 | 房态无法确认或工具失败 | 区分无法核验与查询失败，提供重试或重新确认 |
| UC-04-E10 | 用户选择、查看或退出 | 绑定酒店/房型链接，或停止查询；不自动购买 |

完整扩展表和禁止行为见：[M1 AI Use Case Package](../../../../docs/prd-2.0-design/07-M1-ai-use-case-package.md)。

## 7. 进入评测时怎么用

不要按“5 个文件 = 5 条测试”执行。建议按下面 7 条连续 Test Journey 走查：

| 测试 Journey | 连续覆盖的节点 | 主要验证目标 |
|---|---|---|

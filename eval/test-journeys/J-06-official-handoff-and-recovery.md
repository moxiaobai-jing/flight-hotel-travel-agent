# J-06：官方交接与恢复

## 测试目的

验证机票规划助手能够把每个候选绑定到自己的官方查看入口，按用户要求尝试自动打开，并在查询中断后安全恢复：

- 用户明确说“打开候选”时，只尝试打开该候选对应的链接；
- 自动打开能力不可用时，如实说明原因并返回该候选的可点击链接；
- 不把组合查询入口冒充成单个航班详情链接；
- 恢复时只复用已确认的目的地、出发地、日期和筛选条件；
- 恢复会创建新的查询轮次，不直接复用旧候选、旧价格或旧完成状态；
- 只做查看交接，不执行购票、支付或订单确认。

本路径使用 `eval/fixtures/J-06-controlled-results.json` 中的受控候选。链接使用 `example.test`，只用于验证绑定关系，不代表真实可用链接。

## 人工走查步骤

### 一、验证候选详情交接

1. 发起一个完整的单程机票查询并完成确认。
2. 等待候选结果返回，记录至少两个候选的候选编号、航班号、价格和日期。
3. 发送自然语言指令：

   > 帮我打开候选 1。

4. 如果本机浏览器权限可用，确认打开的入口对应第一个候选的航班、日期和路线，不应跳到第二个候选或泛化的组合查询页。
5. 如果自动打开权限不可用，确认助手明确说明未能自动打开，并返回候选 1 的可点击详情链接。
6. 点击候选 1 的兜底链接，再返回结果卡片，验证候选 2 的入口与候选 1 不同且绑定正确。
7. 确认助手没有执行购买、支付、下单或订单确认。

推荐话术：

> 打开候选 1 的详情。

预期：优先尝试只打开候选 1 的官方查看入口；若无法自动打开，则返回候选 1 的详情链接，并保留候选 ID 与航班信息的对应关系。

### 二、验证恢复查询

1. 发起包含多个出发地或多个日期的查询，确认后开始搜索。
2. 在查询进行中发送：

   > 停止查询，我暂时不看了。

3. 确认助手停止继续调用航班查询工具。
4. 再发送：

   > 继续查。

5. 确认助手基于原来已经确认的条件重新发起一轮查询，并重新显示本轮进度；如果只恢复未完成组合，进度总量应等于本次实际恢复的组合数。
6. 确认新轮次不会直接复用上一轮的候选卡片、价格或“已完成”数量。
7. 如果用户在恢复前修改目的地、出发地、日期或筛选条件，确认助手会先复述新条件并等待再次确认，不得静默恢复旧查询。

## 受控 Demo

运行：

```bash
node tools/run-controlled-j06.mjs
```

预期检查点：

- `hz-1` 只能打开 `hz-1` 的官方链接；
- 恢复后的轮次编号比上一轮增加 1；
- 恢复后的候选列表为空，完成数从 0 开始；
- 恢复条件与已确认条件一致；
- 输出明确声明只验证官方查看入口，不执行购票或支付。

## 通过标准

- 每个候选都有唯一、可追踪的详情链接；
- 用户明确要求打开时，自动打开成功或明确说明失败并提供同一候选的链接；
- 候选详情链接不会串候选、串日期或串路线；
- 无详情链接时明确显示“暂无详情”，不自行伪造链接；
- 停止后没有新的查询调用；
- 恢复会创建新轮次并重新查询，不直接展示旧结果；
- 恢复只使用已确认条件；
- 全流程不触发购票、支付或订单操作。

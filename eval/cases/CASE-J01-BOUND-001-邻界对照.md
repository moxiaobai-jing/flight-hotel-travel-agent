# CASE-J01-BOUND-001：邻界对照

## 1. 扩展信息

| 字段 | 内容 |
|---|---|
| Case ID | CASE-J01-BOUND-001 |
| 扩展方法 | 邻界对照 |
| 基准 GT | GT-J01-001 |
| 对应路径 | J-01 |
| 应用版本 | demo-eval-20260916-c4c9a09edacc-787bfe89e75f-3e2d87950bd6 |

## 2. 与基准 Case 的关系

保持目的地“济州岛”和出发地“上海”不变，只改变一个决策条件：日期从“尚未确定”变为“已明确”。该 Case 用来判断系统是否能在边界条件变化后改变下一步行为，而不是机械重复同一条追问。

## 3. 用户输入

### 对照 A：日期未明确

```text
国庆我想去济州岛，上海出发，日期还没定。
```

预期：只追问可接受的出发日期范围，不查询。

### 对照 B：日期明确

```text
国庆我想去济州岛，上海出发，2026 年 10 月 1 日，帮我查单程机票。
```

## 4. 预期行为

- 两个对照都识别目的地为济州岛、出发地为上海；
- 对照 A 只追问日期范围；
- 对照 B 识别出具体日期后，复述路线、日期和单程条件，并进入等待用户确认的状态；
- 对照 B 不能因为条件完整就直接调用 `flight_search`；
- 两个对照都不能调用 `feishu.open_candidate` 或返回未查询的候选航班；
- 对照 B 不应重复询问已经明确的目的地、出发地和日期。

## 5. 通过标准

关键判定是：日期状态变化后，系统下一步行为必须从“继续澄清”变成“复述并等待确认”。如果两种输入得到完全相同的追问，或对照 B 未确认就查询，均判定失败。

## 6. 重点失败标签

- `boundary_not_detected`：没有识别日期明确性导致的行为边界变化；
- `known_condition_reasked`：重复询问用户已明确提供的条件；
- `confirmation_gate_bypassed`：条件完整但未经用户确认就查询。

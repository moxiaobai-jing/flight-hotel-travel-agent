# 酒店规划专项 Skill（P0）

## 职责

负责酒店对象识别、入住条件确认、房态与房型查询、酒店细节参考、附近替代和原始供应商交接。它由 `travel-planning` 统一入口调用，不负责统一 onboarding、跨类型路由或安全预审。

## 调用前提

只有同时满足以下条件，统一入口才可以调用本 Skill 或 `hotel_search`：

- 已识别出酒店名称或可核验的酒店对象；
- 已确认入住日期和离店日期；
- 已确认入住成人数；
- 房间数缺失时按 1 间处理，并在确认信息中展示；
- 酒店名称、入住日期、离店日期、入住成人数和房间数已经齐全且无冲突；酒店条件补齐后直接查询，不要求用户再次回复“确认”；
- 安全预审允许继续执行。

缺少入住日期或离店日期时，必须追问“哪天入住、哪天离店”；图片或文字只有月日没有年份时，按当前年份处理并在确认摘要中说明，不单独追问年份。入住人数未提供时按 1 位成人进入确认摘要，允许用户修改；P0 不要求在助手内确认儿童数、床型或其他下单信息，除非用户主动提供并要求筛选。

## 输入与抽取

支持自然语言、酒店截图、订单截图、攻略文字和酒店链接。至少尝试抽取：

- 酒店名称、英文名或可定位的酒店对象；
- 图片或文字同时出现中文名和英文名时，必须分别保留中文主名称与英文别名；例如“扎斯戈酒店 / Zasgo Hotel”。调用 `hotel_search` 时将英文名放入 `hotel_aliases`，不得只传中文名。
- 入住日期、离店日期；
- 成人数；
- 房间数，缺失时默认为 1；
- 用户明确提出的价格、距离、房型或取消要求。

图片中只有酒店名和地址、没有入住日期时，不调用查询工具；先补问日期。无法区分酒店品牌、分店或城市时，先澄清酒店对象，不凭名称猜测。

供应商名称重试由工具在后台完成：先查中文主名称，再查英文名、别名或中英文组合名称；中间某一轮无结果不向用户展示，也不能直接判断无房。所有候选都无法命中时，只能说“当前无法核验该酒店”。

## 同款房态查询

1. 只查询用户确认的酒店、日期、成人数和房间数。
2. P0 当前只调用 RollingGo；不再调用 TourMind，也不做多供应商交叉比较。
3. 参考房型用于优先核验，但默认查询该酒店目标日期的全部可售房型，不把参考房型当成唯一筛选条件。
4. 只能把工具明确返回的结果说成“有房”或“无房”；一个供应商有房不能推断另一个供应商也有房。
5. 返回 `available` 时，列出工具返回的全部可入住的房型、价格、餐食、取消政策、供应商和详情/购买链接（以工具实际提供为准）；参考房型需单独说明是否可售。
6. RollingGo 明确返回无房、售罄或指定房型不可售时，说明具体状态；不使用宽泛“无匹配”。
7. RollingGo 返回 `source-unconfirmed` 或 `tool-error` 时，只能说“当前无法核验房态”，不得推断有房或无房。
8. 返回 `tool-error` 时，说明查询失败，并保留可重试的已确认条件。

## 酒店细节与评价

用户要求查看酒店时，可以返回地址、距离、评分、近期评价摘要、设施、房型说明和原始详情链接。评价只能作为参考，必须标注来源和查询时间；评价不能证明当前房态、价格或可购买性。

## 附近替代

- 同款无房、价格过高或用户明确表示不可接受时，先向用户说明当前状态。
- 只有用户明确同意或提出“找附近/相近/更便宜的酒店”后，才可使用 `nearby`、`cheaper` 等替代范围。
- 替代排序必须依据用户已确认的条件；若用户没有指定，默认先按距离，再按价格，但应在查询前说明。
- 替代酒店必须单独标注为“附近替代”，不能冒充原酒店或同款房型。
- 每个候选都要尽量返回可核验的原始供应商详情/购买链接；没有链接时标注“待核验”。
- 当前 RollingGo 附近查询默认以目标酒店为中心 3 公里内；用户明确提出其他距离或每晚预算上限时，才传入对应筛选条件。
- 附近候选必须同时具备坐标核验、真实房型、价格和详情链接；只有酒店名称或泛搜结果不能作为可入住候选展示。

## 结果与购买交接

酒店结果使用结构化文字，不改变既有航班结果格式。每个候选至少包含：

```text
酒店名｜房型｜价格
入住日期 → 离店日期｜入住人数｜房间数
房态：有房 / 指定房型不可售 / 目标日期售罄 / 当前无法核验
取消与餐食：以工具返回为准
查看详情
```

链接必须来自工具返回且与候选绑定。用户最终在原始供应商页面查看环境、卫生、床型和实时房态，并自行购买；本 Skill 不创建订单、不支付、不确认下单、不改订和不取消。

## 失败关闭

酒店对象、日期、成人数或链接无法确认时，不调用外部酒店查询。工具没有返回房型、价格或可购买链接时，不补造这些信息。任何数据源返回的“有房”都要标注数据源和查询时间，并提示用户下单前在原始页面再次核验。

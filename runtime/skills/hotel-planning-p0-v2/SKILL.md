# 酒店规划专项 P0 v2

读取 `../travel-planning-p0-v2/references/hotel-contract.md` 和 `../travel-planning-p0-v2/references/failure-and-safety.md`。本 Skill 独立负责酒店房态、房型、评价参考、附近替代和详情交接，不负责统一 onboarding。

## 调用前提

- 已识别并确认酒店名称或可定位酒店对象；
- 已确认入住日期和离店日期；
- 截图或文字缺少年份时，按当前年份处理，并在确认摘要中透明标注，不单独追问年份；
- 入住人数已在确认摘要中展示，未提供时默认 1 位成人；
- 房间数已在确认摘要中展示，未提供时使用 1 间；
- 酒店名称、入住日期、离店日期、入住人数和房间数已经齐全且没有冲突；酒店条件补齐后直接查询，不再要求用户额外回复“确认”；
- 安全预审允许继续执行。

## 酒店名称抽取与供应商重试

- 图片或文字中同时出现中文名和英文名时，必须同时保留两个名称，不得只留下中文名；例如“扎斯戈酒店 / Zasgo Hotel”。
- 查询工具以中文名作为主名称，并将英文名、别名或中英文组合名称作为 `hotel_aliases` 传入。
- 供应商查找不到主名称时，由工具在后台依次尝试别名和组合名称；中间失败不向用户展示，也不能直接说“无房”。
- 只有所有名称候选都查不到目标酒店，才返回“当前无法核验该酒店”；这不等于目标日期无房。

缺少入住日期或离店日期必须追问。不能因为成人数和房间数采用默认值而再次阻塞查询，也不能在条件已经齐全时增加二次确认。

## 结果责任

只能把工具明确返回的房态说成有房、参考/指定房型不可售或目标日期售罄。房型截图或订单中的房型是优先核验对象，不是默认的唯一筛选条件。每个工具返回的可售房型都要返回名称、可用价格、房型差异和绑定详情链接；参考房型不可售时，必须列出该酒店已核验到的全部其他可售房型。酒店评价和推荐理由必须有来源和查询时间。

目标酒店无房、价格不合适或仅剩房型不合适时，先说明具体原因，再等待用户同意。用户同意后默认在三公里内按距离优先查附近酒店，最多三个候选；每个候选都要有距离、特点/评价、推荐理由、可售房型和详情链接。

附近查询默认以目标酒店为中心 3 公里内；用户明确提出每晚预算上限时，同时传入预算条件。候选必须经过坐标距离核验，并且有真实房型、价格和详情链接；不能用仅返回酒店名称的泛搜结果冒充可入住候选。

## 失败关闭

无法核验时不能说有房或无房；工具失败不能说售罄；缺少房型、价格或链接时不能补造。用户最终自行进入原始供应商页面核验并购买，本 Skill 不创建订单、不支付、不改订、不取消。

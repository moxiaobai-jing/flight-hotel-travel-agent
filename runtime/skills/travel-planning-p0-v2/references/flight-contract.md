# 航班契约（PRD 1.0）

## 输入字段

- 出发地城市/机场
- 抵达地城市/机场
- 出发日期；缺少年份时默认当前年，但确认摘要必须展示完整年份
- 出发时间、抵达时间（图片有则抽取）
- 航班号可选；缺少航班号不能阻止查询
- 用户当次偏好：价格优先、直飞、时间或可接受最长飞行时长

部分字段识别规则：截图或文字中的字段必须逐项判断并保留。某个字段被打码、模糊或缺失时，只追问该字段，不得把其他已经识别的字段一起清空。例如出发地和出发时间清晰、抵达地被打码时，应保留出发地和出发时间，只将抵达地列为缺口；航班号缺失不阻断后续核验。通过 `flight.time_infer` 根据抵达日期、出发时间和全程时长推算出的抵达时间，或根据抵达日期、抵达时间和全程时长推算出的出发时间，均视为已确定字段，必须写入条件并从缺口中移除，不得再次追问该时间；此时只询问仍不确定的出发/抵达机场。

P0 不在助手内确认乘机人数、儿童数、行李或购买人信息；这些属于原始供应商详情页的下单信息。

## 查询前确认

确认摘要必须展示已识别的出发地、抵达地、完整日期、出发/抵达时间和已识别航班号（如有），并等待用户确认。

## 同款判定

- 有航班号：优先按航班号以及日期、出发地、抵达地核验。
- 无航班号：必须同时完全匹配出发时间和抵达时间；可以返回多个满足完全匹配的候选，并显示每个航班号。
- 缺少出发时间或抵达时间：若无法唯一核验，必须说明缺口并追问；不得用相近时间冒充同款。

## 替代承接

同款不存在、票价不可接受或用户明确要求替代时，先告诉用户具体状态，再询问是否扩大范围。精确核验阶段不询问价格偏好，也不把默认“价格优先”展示给用户；只有用户明确授权扩大范围后，才进入候选推荐并按默认或用户指定偏好排序。可提议：当天前后三小时、前后一天或用户指定日期窗口，以及价格优先、直飞优先或最长飞行时长等偏好。

用户未同意前不得自动调用替代查询。用户明确同意前后三小时后传 `alternative_scope=plus_minus_3_hours`；用户明确同意当天任意时段后传 `alternative_scope=same_day`。只说“确认”不等于同意扩大范围。替代结果不得标记为同款。

## 输出字段

沿用 V1.0：候选编号、航空公司、航班号、价格、日期/星期、出发地→目的地、出发时间、抵达时间、飞行时长、总耗时、直达、点击详情。保留工具返回的每个候选对应链接。

# 酒店契约（PRD 1.0）

## 输入与默认值

从截图、文字、链接或订单中抽取：酒店名/可定位对象、入住日期、离店日期、入住人数、房间数，以及用户明确提出的价格、距离、房型、早餐或取消偏好。

- 入住日期和离店日期是查询必要字段，缺失就追问。
- 截图或文字只给出月、日而没有年份时，按当前年份处理；在确认摘要中写明“年份未提供，按当前年份处理”，不单独追问入住年份。用户可以在确认时一起修改日期。
- 入住人数未提供时，确认摘要按 1 位成人展示；不为了这个默认值重复追问。
- 房间数未提供时，确认摘要按 1 间展示。
- 房型不是查询前必要字段。截图或订单中的房型属于优先核验对象，不默认把查询限制为这一种房型；查询目标是该酒店在目标日期的全部可售房型。

查询前可展示摘要：酒店名称、入住日期、离店日期、入住人数、房间数和已提供的其他筛选条件。房型参考存在时，应说明“优先核验该房型；如果不可售，同时返回该酒店其他可售房型”。上述字段齐全且无冲突时直接查询，不要求用户再次回复“确认”。

## 同款房态

目标酒店查询后按以下状态输出：

- `available`：明确写“有房”，返回酒店描述/评价参考，并列出工具返回的全部可售房型。若有截图或订单中的参考房型，先标注该房型是否可售，再列出同一酒店其他可售房型。每个房型写清名称、床型/面积（有数据才写）、餐食、取消、价格和独立详情链接。
- `room_unavailable`：参考房型或用户指定房型不可售；明确说明该房型状态，并列出该酒店已核验到的全部其他可售房型，不把其他房型冒充指定房型。
- `sold_out`：目标日期没有可售房型，明确写“目标日期售罄”。
- `source_unconfirmed`：当前无法核验，不判断有房或无房。
- `tool_error`：查询失败，不把技术错误写成售罄。
- `quote_or_link_invalid`：报价或详情链接失效，提示重新核验。

酒店描述和评价只能作为参考，必须带来源和查询时间；不能用酒店基础信息证明当前房态。

## 附近替代

同款酒店无房、仅剩房型不符合或价格不合适时，先说明原因，并询问是否找附近替代。用户同意且未给出其他范围时，默认三公里内、距离优先，最多返回三个候选。

每个候选必须单独包含：酒店名、距目标酒店距离、酒店特点/评价摘要、推荐理由、可售房型及区别、价格、餐食/取消、查询时间、来源和详情链接。候选没有房型或价格证据时，标记无法核验，不补造。
